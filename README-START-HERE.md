# Frontier Quartermaster — ერთიანი GitHub პაკეტი

ეს არის **არსებულ Supabase პროექტთან დასაკავშირებელი** საიტი, არა დამოუკიდებლად გამართული სისტემა. ZIP-ში არ არის არც პაროლები, არც საიდუმლო გასაღებები.

## GitHub-ზე ატვირთვა

1. ZIP გაშალე. რეპოზიტორიის მთავარ (`main`) ფილიალში ძველი `index.html` შეცვალე ახალი `index.html`-ით.
2. `config.js` გახსენი ტექსტურ რედაქტორში და შეავსე Project URL, **publishable/anon** key და სამივე ანგარიშის Auth ელფოსტა (იგივე, რაც უკვე შექმენი Supabase Authentication-ში). ეს ელფოსტები საჯარო გახდება GitHub-ზე, რადგან რეპოზიტორია Public-ია. თუ არ გინდა მათი გამოქვეყნება, არ ატვირთო ამ სახით; დაგვჭირდება უსაფრთხო server-side username mapping.
3. ატვირთე `config.js` იმავე დონეზე, სადაც `index.html` დევს. სხვა ფაილები GitHub Pages-ს არ სჭირდება.
4. GitHub Settings → Pages-ში დარწმუნდი, რომ საიტი ქვეყნდება `main` / root-დან, ან არსებული Actions workflow სწორად მუშაობს.
5. სურვილის შემთხვევაში Supabase SQL Editor-ში გაუშვი `optional_four_slot_update.sql`, რომ ბაზამაც 4 აქტიური სლოტი შეზღუდოს. **ძველი schema.sql ხელახლა არ გაუშვა** — უკვე არსებული ბაზის მიგრაცია ცალკე უნდა შემოწმდეს.
6. სამივე მომხმარებლით შეამოწმე შესვლა; სატესტოდ მიიღე მარაგი, გასცე 1 ნივთი, დააბრუნე, მონიშნე დაკარგულად, შეამოწმე დღის შეჯამება და მეორე ბრაუზერში სინქრონიზაცია.

## უსაფრთხოება და შეზღუდვები

- საიტის შესვლის ფორმა მხოლოდ **სახელს და პაროლს** აჩვენებს; რეალური ავტორიზაცია Supabase Auth-ის ელფოსტა/პაროლით ხდება.
- GitHub-ის Public რეპოზიტორიაში `config.js`-ის მონაცემები ხილულია. Publishable/anon key საჯარო გამოყენებისთვისაა, მაგრამ **service_role/secret key არასდროს გამოაქვეყნო**.
- მონაცემები დაცულია მხოლოდ მაშინ, თუ Supabase RLS და RPC უფლებები სწორადაა გამართული; საჭიროა რეალური უსაფრთხოების ტესტი.
- `initial_qty` უცვლელია; დამატება აისახება `added_qty`-ში.
- დღის თარიღი Europe/Paris დროის სარტყლით ითვლება.
- ახალი გაცემა მხოლოდ დღევანდელ თარიღზეა შესაძლებელი; სხვა დღის ჩანაწერების ნახვა შეიძლება.
- ყველა დაკარგულად მონიშვნა და ყველა დაბრუნება მოქმედებს არჩეული **გაცემის დღის** ჯერ ღია ჩანაწერებზე.
- საწყისი კატალოგის რაოდენობები ამ პაკეტში არ იცვლება.
- სანამ ნამდვილ აღრიცხვაში გამოიყენებ, აუცილებელია სარეზერვო ასლი და ფუნქციური ტესტები.
